# orc-crds

Helm chart for installing the [OpenStack Resource Controller (ORC)](https://k-orc.cloud/) Custom Resource Definitions.

This chart installs only the CRDs. Install the [orc](../orc/) chart separately to deploy the controller.

## Install

```bash
helm install orc-crds oci://quay.io/orc/helm/orc-crds --version <version>
```

## How CRDs are managed

The `crds/` directory is a symlink to `config/crd/bases/`, so no copying or
generation step is needed. The CRD files themselves are generated by
`controller-gen` via `make manifests`.

## Values

| Parameter | Default | Description |
|-----------|---------|-------------|
| `nameOverride` | `""` | Override the chart name used in resource names |
| `fullnameOverride` | `""` | Override the full resource name prefix |
| `rbac.aggregate.enabled` | `true` | Create ClusterRoles aggregating ORC resources into the builtin `view`, `edit` and `admin` roles |

## Aggregated ClusterRoles

The chart also installs two ClusterRoles, `<release>-aggregate-view` and
`<release>-aggregate-edit`, that aggregate all ORC kinds into the builtin
`view`, `edit` and `admin` roles. The view role holds the read verbs and is
aggregated into all three builtin roles; the edit role holds only the write
verbs and is aggregated into `edit` and `admin`. They are generated by `hack/gen-helm.sh` from
the CRDs (do not edit `templates/aggregate-*-clusterrole.yaml` by hand; run
`make generate`). Disable them with `rbac.aggregate.enabled=false`.

Helm does not upgrade or delete the contents of `crds/` on `helm upgrade`, but
it does manage the resources in `templates/`, so the roles are kept up to date
across upgrades.
